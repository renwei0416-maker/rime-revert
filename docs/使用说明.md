# 撤回上屏 使用说明

**一句话**：字打上屏之后，输入 `qq/`（或按一个你设的组合键），把刚上屏的那段字删掉；还能用
`zz;`、`ff;` 这类触发码，直接替你按一下常用快捷键（撤销、全选、删到前一个符号……）。

**这包里有**：`sendKeyCode.dll`、`revert.lua`，以及本说明。

---

## 一、装在哪里

两个文件**放在同一个目录**，推荐：

```
<Rime 用户目录>\lua\wanxiang\ziji\sendKeyCode\
├─ sendKeyCode.dll
└─ revert.lua
```

`<Rime 用户目录>` 一般是 `%APPDATA%\Rime`（例如 `C:\Users\你的名字\AppData\Roaming\Rime`）。
小狼毫用户可以在开始菜单里点"小狼毫 → 用户文件夹"直接打开它。

三条不能违反的规矩：

1. **两个文件必须放在同一个目录。**
2. **dll 的文件名不能改**，必须叫 `sendKeyCode.dll`。
3. **目录名可以随便换**，但换了要同时改一处设置（见下）。

### 想换个目录？

不用改代码，在你的 `*.custom.yaml` 里加一行就行（路径写成**相对用户目录**、用正斜杠 `/`）：

```yaml
patch:
  "revert/dll_dir": "lua/my/sendKeyCode"
```

然后把两个文件一起挪到 `<用户目录>\lua\my\sendKeyCode\`，并记得把下面"启用"那行的名字也跟着改。

---

## 二、启用（在方案里加一行）

加在方案的 **`engine` → `processors`** 列表里（**不是 translators**，也不是 filters）。

**做法一：直接改进方案文件**（`xxx.schema.yaml`）

```yaml
engine:
  processors:
    - lua_processor@*wanxiang.ziji.sendKeyCode.revert
```

**做法二：用补丁文件**（推荐，不动原方案）——在你的 `xxx.custom.yaml` 里写：

```yaml
patch:
  engine/processors/@before 0: lua_processor@*wanxiang.ziji.sendKeyCode.revert
```

> 名字怎么写：文件放在 `<用户目录>\lua\` 下的哪条路径，就照着写、把 `\` 换成 `.`、去掉最后的 `.lua`。
> 例：`<用户目录>\lua\wanxiang\ziji\sendKeyCode\revert.lua` → `wanxiang.ziji.sendKeyCode.revert`。
> 冒号只写一个：`@before 0:`。写成 `@before 0::` 是笔误，会报风格错误。

**为什么推荐放在最前面**：放在中间或后面时，你按的触发键可能先被别的组件吃掉（把 `;` `,` `.`
改键、把符号当标点提交、按前缀抢串），表现就是"按了没反应"。放在最前面，本组件先看一遍每个
按键：只有命中你的触发码/组合键才拦下这一键，其它按键全部原样放行，不会影响正常打字。

> **如果之前按老说明把它挂在 `translators` 里，请把那行删掉**（或改成上面这样）。
> 挂在 `translators` 里也能触发，但那是在引擎翻译途中的回调里干活，是小狼毫崩溃的根源。

加完之后 **重新部署**（任务栏小狼毫图标右键 → 重新部署）。不重新部署不生效。

## 三、怎么用

有两种触发方式，**默认是第一种**（打 `qq/`）。

### 方式一：打触发码（默认 `qq/`）

| 操作 | 结果 |
| --- | --- |
| 打一段字上屏，再输入 `qq/` | 刚上屏的那段字被删掉（`qq/` 本身不会上屏） |
| 紧接着再输入一次 `qq/` | 继续往前删一次（最多能连着撤回最近 50 次上屏） |
| 还没有任何上屏记录时输入 `qq/` | 什么也不做（不会乱删你手打的内容） |
| 连着猛按几下 `qq/` | 中间那几下会被忽略（不会重复删），稍等一下再按就能继续往前删 |

### 方式二：按组合键（可选，和方式一可以同时用）

在 `custom.yaml` 里写一行，例如：

```yaml
patch:
  "revert/hotkey": "Control+slash"     # 也就是 Ctrl+/；也可以写 "Ctrl+/"
```

| 操作 | 结果 |
| --- | --- |
| 按 Ctrl+/ | 删掉刚上屏的那段字（这个组合键不会上屏、也不会留下任何字符） |
| 正在打字（有没上屏的编码）时按 | 这一次按下会被吃掉但不删字（避免删错，再按一次即可） |

**默认不启用**（`revert/hotkey` 不写就是空的，只有 `qq/`）。写了以后两种方式**同时有效**：
`qq/` 照旧能用，Ctrl+/ 也能用。想只留一种时这样写：

| 想怎样 | 怎么写 |
| --- | --- |
| 只用文本触发码（默认） | `revert/hotkey` 留空、不写这一行 |
| 两种都要 | 写上 `"revert/hotkey": "Control+slash"` |
| 只要组合键 | 写上组合键，再加一行 `"revert/trigger": "none"` 关掉文本触发码 |

组合键的好处：**不需要** `alphabet` 里有任何字符、不会被标点或按键绑定抢走、也几乎不会误触。

### 方式三：打"快捷触发码"，替你按一下常用快捷键（可选，默认一个都不启用）

打两个字母加一个 `;`，就等于在目标程序里按了一下对应的快捷键。默认表（**默认全部关闭**）：

| 打这个 | 等于按 | 作用 |
| --- | --- | --- |
| `zz;` | Ctrl+Z | 撤销 |
| `yy;` | Ctrl+Y | 重做 |
| `aa;` | Ctrl+A | 全选 |
| `cc;` | Ctrl+C | 复制 |
| `vv;` | Ctrl+V | 粘贴 |
| `xx;` | Ctrl+X | 剪切 |
| `ss;` | Shift+Home | 从光标选到行首 |
| `gg;` | End | 跳到行尾 |
| `tt;` | Home | 跳到行首 |
| `ww;` | Ctrl+Shift+← | 选中光标前的一个词（可连按） |
| `bb;` | Ctrl+Backspace | 删前一个词 |
| `rr;` | Ctrl+Delete | 删后一个词 |
| `hh;` | Ctrl+Home | 跳到文首 |
| `ee;` | Ctrl+End | 跳到文末 |
| `dd;` | Ctrl+Shift+Backspace | 保留项（注意：不是所有程序里这都是"删整行"） |
| `kk;` | Ctrl+Shift+K | 删除整行（VS Code 等） |
| `ff;` | 内置动作 | 删到光标前第一个符号（**只删到符号后面，符号保留**） |

**一次启用整套**：

```yaml
patch:
  "revert/shortcuts": "@defaults"
```

**只启用其中几个**（触发码和按键都随你改）：

```yaml
patch:
  "revert/shortcuts": "zz;=ctrl+z  yy;=ctrl+y  ss;=shift+home  ff;=@to-symbol"
```

写法：一项一项写，`触发码=动作`，用空格隔开。可以和默认表混着用：
`"@defaults xy;=ctrl+shift+right"` 表示"先展开整套默认表，再加上我自己这项"。
**注意别和默认表撞码**：`"@defaults ww;=ctrl+shift+left"` 会因为 `ww;` 重复而**两个都不生效**
（按你定的规矩：重复的快捷设置一律不生效，日志里会有 `duplicate shortcut trigger disabled: ww;`）。

动作的三种写法：

| 动作 | 意思 |
| --- | --- |
| 按键序列，如 `ctrl+z`、`shift+home`、`ctrl+shift+k` | 发一次这个组合键 |
| 多步（逗号隔开），如 `shift+home,shift+left` | 依次发多步；`ss;` 想连换行一起选就写这个 |
| `@to-symbol` | 删到前一个符号（保留符号） |
| `@to-symbol-include` | 删到前一个符号（连符号一起删） |
| `@delete` | 同 `qq/`：删掉最近一笔上屏 |

可用的键名（大小写都行）：单字母 `a`-`z`、单数字 `0`-`9`，以及
`backspace`、`tab`、`return`/`enter`、`escape`/`esc`、`space`、`end`、`home`、`left`、`up`、
`right`、`down`、`pageup`、`pagedown`、`insert`、`delete`/`del`、`capslock`、`f1`-`f12`、
`numpad0`-`numpad9`、`minus`、`equal`、`comma`、`period`、`slash`、`semicolon`、`quote`、
`grave`、`bracketleft`、`bracketright`、`backslash`；修饰键 `ctrl`/`control`、`shift`、
`alt`、`win`/`super`/`cmd`。

"符号"是哪些字符（`@to-symbol` 用）也能改，默认是一串中英标点：

```yaml
patch:
  "revert/symbols": "，。！？；：、,.!?;:"
```

想连换行也算符号就写 `\n`，制表符写 `\t`。默认**不**把 `-` `_` 当符号（这样英文里的连字符、
变量名里的下划线不会把删除截断），需要就把它们加进去。

几条规矩：

- 触发码**至少两个字符**，字符必须在方案的 `speller/alphabet` 里（和第 1-3 条注意事项一样）。
- 只有"已打出的编码正好等于前缀 + 这一键是最后的字符"才触发；打完前缀后按别的键不受影响。
- **触发码不能重复**（同一项写两遍、或与 `revert/trigger` 撞码）：涉及的那些项一律不生效，
  日志里会写 `duplicate shortcut trigger disabled: xx;`。所以别把 `zz;` 同时给两个功能。
- 按键序列写错（比如 `ctrl+nope`）不会生效，日志里会写 `bad key sequence disabled: …`。
- 三种方式**可以同时用**，互不干扰；快捷键不受 `revert/debounce_ms` 影响。

## 四、注意事项（没反应，多半是这里）

第 1-3 条只和"打触发码"有关（方式一和方式三的触发码都适用）；用组合键（方式二）的话可以跳过。

1. **触发码的每个字符都得在方案的 `speller/alphabet` 里。** 默认 `qq/` 需要 `q` 和 `/`。
   检查方案 `xxx.schema.yaml`：
   ```yaml
   speller:
     alphabet: zyxwvutsrqponmlkjihgfedcba/
   ```
   少了 `/`（或你用的别的符号）就永远触发不了。
2. **这个符号别已经被按键绑定用掉了。** 很多方案把 `;` `,` `.` 绑给了别的功能，
   被绑走的话触发码收不到。换个没被占用的符号（`/` 通常没问题）。
3. **触发码不要以 `/` 开头**（`/wx`、`/emoji` 这类是方案的符号输入，会撞车）。
4. **改完一定要重新部署**，然后等一两秒再试。
5. **删之前不要动光标。** 它只知道"上屏了几个字"，不知道你现在光标在哪；
   上屏后如果点过鼠标、按过方向键、换过行或切过窗口，再触发就会删到别的地方。
6. **按键是稍等一下才发出的**（大约 0.1 秒后才开始删），删很长的内容还会再花一点时间。
   这期间别急着打字或点鼠标，否则可能删到别处；连着猛按也不会更快，中间那几下会被忽略。

## 五、想改设置（都不用重新编译）

在 `xxx.custom.yaml` 的 `patch:` 里写，不写就用默认值：

```yaml
patch:
  "revert/trigger": "qa/"          # 方式一的触发码，默认 "qq/"
  "revert/hotkey": "Control+slash" # 方式二的组合键，默认空（不启用）
  "revert/shortcuts": "@defaults"  # 方式三的快捷键表，默认空（一个都不启用）
  "revert/symbols": "，。！？；：、,.!?;:"   # @to-symbol 认定的符号，默认一串中英标点
  "revert/stack_size": 50          # 最多能连着撤回几次上屏
  "revert/max_backspaces": 500     # 一次最多删多少个字符
  "revert/debounce_ms": 200        # 防抖（毫秒），防一次触发删两遍
  "revert/dll_dir": "lua/wanxiang/ziji/sendKeyCode"   # 两个文件所在目录
```

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `revert/trigger` | `"qq/"` | 方式一的触发码。要求见第四节第 1-3 条；写 `"none"`/`"off"`/`"-"` 表示关掉它 |
| `revert/hotkey` | 空 | 方式二的组合键，例如 `"Control+slash"`、`"Ctrl+/"`、`"Alt+Z"`；不写=不启用，写了两种方式都能用 |
| `revert/shortcuts` | 空 | 方式三的快捷键表，见第三节；写 `"@defaults"` = 启用默认那 17 项；不写=一个都不启用 |
| `revert/symbols` | 一串中英标点 | `@to-symbol` 认定哪些字符是"符号"；支持 `\n` `\t` `\\` 转义 |
| `revert/stack_size` | `50` | 能连续撤回几次上屏；想撤得更远就调大（上限 1000） |
| `revert/max_backspaces` | `500` | 一次最多删多少字符；超出部分不删（上限 10000） |
| `revert/debounce_ms` | `200` | 防抖，正常不用动；**只对方式一的文本触发码生效**，快捷键不受它影响 |
| `revert/dll_dir` | `lua/wanxiang/ziji/sendKeyCode` | 两个文件所在目录（相对用户目录） |

值写得离谱（负数、特别大）会自动调到安全范围，不会出错。改完记得**重新部署**。

需要一次删超过 10000 个字符（几乎用不到）时才要重新编译 dll，方法见 `重新编译说明.md`。
**另外**：方式三（快捷触发码）要求 dll 是配套的新版——旧版 dll 里没有 `press_keys`，装了也发不出
快捷键，日志里会写 `press_keys is unavailable`。只要按 `重新编译说明.md` 重编一次即可（两个文件都要换新）。
**再另外**（v7）：`ss;`（Shift+Home）、`ww;`（Ctrl+Shift+←）这类"带修饰键选中"的动作，只有
**34203 B 那版 dll** 才正常——更早的 dll 发出的按键缺少扫描码，会被输入法把 Shift/Ctrl 吃掉，
表现就是"光标跳过去了、但没有选中"。这种情况**只替换 `sendKeyCode.dll`** 就行，`revert.lua`
和配置都不用动。

## 六、确认装好了 / 出问题怎么查

1. **最简单的确认**：随便打一段字上屏，再输入 `qq/`（或按你设的组合键），字被删掉就是好了。
2. **看日志**：Windows 上在 `%TEMP%\Rime\` 文件夹里，打开最新的日志，搜 `revert.lua`。
   启用成功时会有一行，写着真正生效的设置，看到它就是配置读到了：
   `revert.lua: mode=text trigger=qq/ hotkey=- shortcuts=- stack_size=50 max_backspaces=500 debounce_ms=200 dll_dir=… module=loaded`
   （`mode=` 会写清哪些方式生效：只有 `qq/` 是 `mode=text`；两种都用是 `mode=hotkey+text trigger=qq/ hotkey=Control+slash`；
   `hotkey` 后面写的是你配的原样文本，如果拼错解析不了，这里也照原样显示、同时会有一行 `cannot parse revert/hotkey`；
   只用组合键是 `mode=hotkey trigger=-`；`shortcuts=` 后面列出真正生效的快捷触发码，例如 `shortcuts=zz;,yy;,ff;`，
   一个都没配就是 `-`。）
   配置里写错的地方也会写进日志：`duplicate shortcut trigger disabled: …`（触发码重复）、
   `bad key sequence disabled: …`（按键序列写错）、`bad shortcut entry ignored`（少了 `=`）、
   `shortcut trigger equals revert/trigger`（和方式一的触发码撞了）。
3. **按顺序排除**：

   | 现象 | 先检查什么 |
   | --- | --- |
   | 打 `qq/` 后 `qq/` 照旧上屏了 | 说明这一键**没被拦下**：那行是不是加在 `processors` 里、有没有写错或被 `#` 注释、有没有**重新部署**；再确认它写在 `@before 0`（放最前），否则会被中间组件先吃掉 |
   | 打 `qq/` 时 `qq/` 没上屏、但字也没被删 | 说明**触发成功了**，问题在删字这一侧：dll 是否叫 `sendKeyCode.dll`、是否和 `revert.lua` 同目录、`revert/dll_dir` 是否正确 |
   | 触发码打不出来 / 变成别的字 | 字符是否都在 `alphabet` 里；符号是否被按键绑定占用 |
   | 按组合键没反应 | 组合键必须先设 `"revert/hotkey"` 才会启用（默认只启用 `qq/`）；名字拼写（`Control+slash`、`Ctrl+/`）、是否被别的软件占用 |
   | 日志里有 `failed to load sendKeyCode` | dll 是不是叫 `sendKeyCode.dll`、是否和 `revert.lua` 同目录、`revert/dll_dir` 写得对不对 |
   | 打 `zz;` 这类触发码没反应 | 方式三**默认全关**：有没有写进 `"revert/shortcuts"`（写了才启用，`"@defaults"` 是启用整套）；触发码是否重复（日志有 `duplicate shortcut trigger disabled`）；按键序列是否写错（日志有 `bad key sequence disabled`）；字母/符号是否都在 `alphabet` 里 |
   | `ss;`（Shift+Home）、`ww;`（Ctrl+Shift+←）、`rr;`（Ctrl+Delete）**只把光标移过去、没选中** | 用的是旧 dll（按键事件只填了 `wVk`、没有扫描码，被输入法把 Shift/Ctrl 吃掉了）。**只换 34203 B 那版 `sendKeyCode.dll`** 即可，配置不用动（见第八节第 10 条） |
   | 日志里写 `press_keys is unavailable` | dll 还是旧版，按 `重新编译说明.md` 重编一次并换成新文件 |
   | 快捷键发出去、程序却没反应 | 目标程序不一定绑了这个键（各程序不同，比如 `Ctrl+Shift+K` 只在部分编辑器是删整行）；**管理员权限运行的窗口收不到**（见第八节第 5 条）；也可能是被别的软件全局占用了 |
   | 打 `ff;` 删的位置不对 | 它是按"上屏记账"往回找符号的：只对**用输入法上屏的字**精确，之后按过退格、动过光标、换过窗口就会偏；符号集可用 `"revert/symbols"` 调整 |
   | 删的位置不对 | 上屏后动过光标（见第四节第 5 条） |

## 八、它做不到的事（先说清楚，省得误会）

1. **光标移过就会删错地方**：它只按"上屏字数"退格，不知道光标现在的实际位置。
2. **emoji 可能少删一个**：有的程序把一个 emoji 算成两个单位。
3. **个别编辑器会多删**：有的"智能退格"一次吃掉一整组字（比如一个拼音音节）。
4. **上屏内容里有换行时删不掉换行**，会一直删到上一行末尾。
5. **目标程序以管理员身份运行时注入无效**（系统的安全限制，与本模块无关）。
6. 它**不是 Ctrl+Z**，是按上屏字数退格；也不能删掉"很久以前"的内容，只记最近
   `revert/stack_size` 次上屏。
7. **方式三发出去的是"真按键"**，程序怎么解释由它自己决定：`Ctrl+Z` 在 Windows 控制台里是
   挂起/结束输入，`Ctrl+Y` 在 bash 系是"粘贴"、`Ctrl+A` 是"到行首"，`Ctrl+Shift+Backspace`
   也不一定等于"删整行"。这些动作**不参与上屏记账**（`@to-symbol`、`@delete` 除外）。
8. **`@to-symbol` 只对"用输入法上屏的字"精确**：它按记账往回找符号，找不到就一路删到记账里
   最早的一笔；上屏之后动过光标、按过退格、换过窗口，位置就可能不对。
9. **`ss;`（Shift+Home）依赖目标程序的 Home 语义**：有的编辑器是"智能 Home"（先跳到行首
   第一个非空白字符处），有些程序在行首时按 Home/Shift+Home 还会往上跑一行。
10. **"带修饰键的动作发出去像没按 Shift/Ctrl"是 dll 版本问题，不是配置问题**：2026-01 之前的
    dll 发出的按键事件只填了键码、没有扫描码，输入法（小狼毫）的键盘钩子会把组合键里的
    Shift / Ctrl 当成"单独按了一下修饰键"吃掉（Shift 还会顺手切中英），目标程序只收到后面那个
    `Home`/方向键 —— 表现就是"光标跳过去了、但没选中"。**换成 34203 B 的 `sendKeyCode.dll`
    即可**（只换 dll，Lua 和配置都不用动）。
11. **`Ctrl+Shift+←`（`ww;`）仍可能被系统抢**：Windows 自己有一组"切换输入法/键盘布局"的热键
   （默认 `Ctrl+Shift` 或 `左 Alt+Shift`）。本模块现在发的是与真键盘一致的按键，理论上不再被
   输入法吃掉；但如果它在你机器上仍然切换输入法，那是系统热键在起作用，可以在
   「设置 → 时间和语言 → 输入 → 高级键盘设置 → 输入语言热键」里把"切换到 XX 键盘布局"改成
   **未分配**（副作用：以后用 `Win+Space` 切换输入法，`Ctrl+Shift` 不再切换）。
